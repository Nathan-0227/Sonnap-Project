## 一句話

**這個專案在「測量」這條軸上做到了計畫書沒要求的深度，
在「介入 → 行為改變」那條軸上把系統建好了但還沒有受測者資料。**

報告的價值不在於假裝三段都完成，而在於**第一段真的紮實、第二段誠實地停在
「已就緒待收案」、第三段主動標明**。第三段那些限制本身就是方法學貢獻——
多數學生專題不會發現自己的資料有這些問題。

### 1.1 睡眠評分

| | |
|---|---|
| 資料量 | **64 晚**（2026-05-29 ~ 2026-09-08） |
| 分數 | 每晚 0–100 ＋ Good/Normal/Poor/Bad |
| 分數範圍 | **27.3 ~ 100.0** |

⚠️ **那 64 晚跨 3 名配戴者**，不是單一使用者。可確認為同一人的最長連續區段是
**41 晚**（`wearer_a`，2026-05-28 ~ 07-27）。

| 區段 | 期間 | 晚數 | 可信 |
|---|---|---|---|
| `wearer_a` | 2026-05-28 ~ 07-27 | 41 | ✅ |
| `unverified` | 2026-07-28 ~ 08-27 | 11 | ❌ 已知多人戴過 |
| `wearer_c`（研究者本人） | 2026-08-28 起 | 12 | ✅ |

分界不是靠記憶，是**用生理訊號本身找的**：對每個候選分界算「左右中位數差 / MAD」，
真正的換人會在多個獨立訊號上同時跳躍。A→B 分界處靜止心率跳 5.73~6.74、
睡眠期間平均心率跳 4.13；前 41 晚內部三個訊號的最大跳躍都 ≤ 1.03。

⚠️ **研究者本人那 12 晚，Tier3 個人化修正值是 0 晚**——`MIN_BASELINE_NIGHTS = 14`，
12 < 14，全部處於冷啟動。報告不能寫「三層評分全數運作」。

### 1.2 評分方法本身（這是最難複製的部分）

- **Tier1/2 基礎分數**：文獻加權，每一項門檻都有 DOI 與第一作者核對，
  完整論證 383 行在 `Research-Background/Garmin手錶分數.md`
- **Tier3 個人化修正**（±12）：戴錶者分段後才算，跨人不比較
- **SRI**：照算照輸出，**刻意不計分**（Czeisler 2026：不同算法的 SRI
  差異大到不能對照外部常模）

⚠️ 有一條紀律值得寫進報告：**要計分，先有文獻**。
`movement_level_mean`、`movement_active_minutes` 至今不進評分，
因為它們的門檻是看資料分布訂的、沒有引文——**不為了多一個指標而破例**。

### 1.3 AI 夢境日記

| | |
|---|---|
| 已生成 | **64 / 64 晚**（全部由 LLM 生成、0 則規則式 fallback） |
| 驗證層 | 四道確定性檢查 |
| 實測 | 中文洩漏 0 晚、夢境含數字 0 晚 |

四道驗證層：夢境不得出現數字、建議中的數字須逐字存在於事實區塊、醫療宣稱禁詞

### 1.4 攝影機偵測層

**⚠️ 攝影機目前授權的計分項目是 0 項。** 這是刻意的結果不是還沒做完，
四個構念逐一判定不可計分的理由寫在 `Research-Background/攝影機分數.md`。

但**偵測層**（「這個測量準不準」，靠人工標註校準，不受文獻紅線約束）有實質進展：

| 改動 | 效果 |
|---|---|
| 照明否決改看空間分布（原本看整幀平均亮度） | **F1 0.50 → 0.79** |
| ROI 用人工標註的幀推導 ＋ 跨晚驗證 | 跨晚 **+0.12**（第 4 晚 F1 0.73 → 0.86） |
| 三晚人工標註後的偵測表現 | **F1 0.84 ~ 0.88** |

⚠️ 舊做法的錯誤值得寫進報告：整幀平均亮度變化 > 4.0 就否決，
**但大幅度翻身在紅外線畫面下本來就會改變整幀平均亮度**——所以它把「正在發生動作」
的幀當成燈光變化丟掉。實測標記附近 ±3 秒被否決 36.2%、其餘時間 1.7%，**21 倍的偏誤**。

⚠️ 同樣值得寫的是**被自己資料否證的那一半**：ROI 的假設是「誤報來自床以外的動作」，
但兩張熱區圖前 30% 的 IoU 是 0.47 / 0.57 —— 誤報大半發生在**跟真動作同一塊區域**。
ROI 對那一類完全無效。**有否證過程才叫驗證。**

### 2.1 行為介入迴圈——技術上通了，沒有受測者

```
手機事件流 → lights_out_at → POST /nightly → 達成度 / 熬夜比率 / 挑戰進度 / 寵物心情
```

這條路端到端實機驗證過。**但目前只有研究者本人的資料。**

⚠️ **挑戰門檻是 n=1 校準的暫定值。** 同一批資料下，`target_bedtime` 設 23:30
達成率 2%、02:30 是 43%、03:00 是 59%——**不能給所有人同一個預設值**。

### 2.2 D2 使用者實測——材料齊備、零筆資料

材料在 `docs/D2_STUDY/`：知情同意書、隱私政策、招募文、前後測問卷、操作手冊。
**尚未招募、零筆受測者資料。**

⚠️ 前後測用的就寢拖延量表改編自 Kroese 等人（2014），**中文是自譯的、未經信效度驗證**，
只能做組內前後比較，不能對照原文獻的常模。

## 第三段：已知壞掉／不能這樣寫

> 逐句的「不能寫 / 要寫成」對照見 [REPORT_CAVEATS.md](REPORT_CAVEATS.md)，這裡只列標題。

| # | 限制 | 一句話 |
|---|---|---|
| 1 | 樣本 | 是「跨 3 名配戴者、64 晚」不是「單一使用者 64 晚」 |
| 2 | `sleep_efficiency` | 分母是「起床 − 入睡」，**不含入睡潛伏期**，系統性高於臨床定義 |
| 3 | `movement_sample_minutes` | 是**取樣分鐘數**不是動作量，與睡眠時長 r=+0.929 |
| 4 | 環境音量 | TAPO 的分貝由 `np.random` 產生，**是假資料**，不參與計分 |
| 5 | 攝影機分數 | 不參與計分，`integrated_score` 標記 PROVISIONAL |
| 6 | SRI | 照算照輸出，刻意不計分 |
| 7 | 挑戰門檻 | n=1 暫定值 |
| 8 | 分數分布 | Good 42/64 偏高，要主動說明 |
| 9 | `lights_out_at` | 量的是「最後一次操作手機」，**是替代測量不是入睡時間** |
| 10 | Tier3 | 研究者本人 12 晚全部冷啟動，**0 晚有修正值** |
| 11 | AI 夢境 | ✅ 64/64 已補齊（2026-09-10）。⚠️ 生成日期不等於量測日期，報告不要寫成「即時生成」 |

### ⚠️ 攝影機錄影的實際狀況（不要略過）

錄過 8 個夜晚，但**整夜可用的資料只有 1 份**。近四晚的紀錄：

| 夜晚 | 結果 |
|---|---|
| 09-06 → 07 | 24 分鐘後斷線 |
| 09-07 → 08 | 無 |
| 09-08 → 09 | 無 |
| 09-09 → 10 | 233 分鐘掛機，**只有 17.9 分鐘有資料** |

根因是網路不是程式：相機只連得上手機熱點（校園的 `eduroam` / `TANetRoaming`
是 WPA2-Enterprise，IoT 相機在規格上就加入不了），而熱點撐不過整夜。
`tapo_netwatch.py` 已加入，用來分辨「熱點關掉」與「筆電漫遊」。

**報告要誠實寫成「攝影機資料收集受限於網路環境，整夜有效樣本 n=1」，
不要用「已建置攝影機監測系統」帶過。**

## 這個專案真正的方法學貢獻

如果報告只能留三頁，留這三件：

1. **每一項計分都說得出出處。** 攝影機四代公式全部失敗，原因相同——
   `2.0/0.1/0.4`、`95/85/70/50/30` 這些數字沒有一個有來源，所以無法辯護也無法比較。
   本專案因此定了「要計分先有文獻」的規則，並且**遵守到寧可讓攝影機零計分項目**。

2. **發現並修正了自己資料的三個錯。** 戴錶者跨人污染 baseline（重跑後 10 晚分數改變、
   6 晚品質等級改變）、照明否決把真動作丟掉（21 倍偏誤）、
   `movement_sample_minutes` 被誤解成動作量。**這些沒有人會來檢查，是自己查出來的。**

3. **對「做得到」與「做不到」分得很清楚。** 三個欄位刻意留 `null` 而不硬湊；
   睡前用量的卡片誠實寫著「這是日彙總，還沒收斂到睡前一小時」；
   攝影機分數標記 PROVISIONAL。
